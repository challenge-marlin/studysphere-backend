## 1. 現在の実装状況

### 1.1 APIエンドポイント

**エンドポイント**: `GET /api/remote-support/capture-records`

**クエリパラメータ**:
- `userId`: オプション、整数（ユーザーIDでフィルタリング）
- `startDate`: オプション、文字列（YYYY-MM-DD形式）
- `endDate`: オプション、文字列（YYYY-MM-DD形式）
- `satelliteId`: オプション、整数（拠点IDでフィルタリング）
- `page`: デフォルト値 `1`（ページ番号）
- `limit`: デフォルト値 `20`（1ページあたりの件数）

### 1.2 処理フロー

1. **ユーザー情報の取得**: データベースから対象ユーザーを取得
2. **S3データの取得**: 各ユーザーのS3バケットから記録データを取得
3. **データのグループ化**: 日付ごとに写真（camera）とスクリーンショット（screenshot）をグループ化
4. **サムネイル生成**: 各日付の最新画像をサムネイルとして決定
5. **ページネーション**: 全件をメモリに展開後、指定されたページと件数でスライス
6. **レスポンス生成**: プレサインドURLを含むJSONレスポンスを生成

### 1.3 ページネーションの実装

```javascript
// バックエンド処理（remoteSupportController.js）
const total = allRecords.length;
const startIndex = (parseInt(page) - 1) * parseInt(limit);
const endIndex = startIndex + parseInt(limit);
const paginatedRecords = allRecords.slice(startIndex, endIndex);
```

**重要なポイント**:
- バックエンドでは**全件をメモリに展開**してからページネーションでスライスしている
- デフォルトでは `limit=20` のため、全件取得するには明示的に大きな `limit` を指定する必要がある

### 2.2 1レコードあたりのデータサイズ

#### 基本フィールド
- `date`: 約10バイト（"2024-01-01"形式）
- `user`: 約100-200バイト
  - `id`: 約4バイト（整数）
  - `name`: 約20-40バイト（日本語名）
  - `login_code`: 約15バイト（"XXXX-XXXX-XXXX"形式）

#### 画像データ配列
各画像オブジェクト（`photos`、`screenshots`、`thumbnails`内の要素）:
- `key`: 約200-300バイト（S3パス文字列）
- `type`: 約10バイト（"camera" または "screenshot"）
- `lastModified`: 約30バイト（ISO 8601形式の日時）
- `url`: 約300-500バイト（プレサインドURL、1時間有効）

**1画像オブジェクトあたり**: 約540-840バイト

#### 1レコードあたりの推定サイズ

| シナリオ | 写真数 | スクリーンショット数 | 推定サイズ |
|---------|--------|---------------------|-----------|
| **最小** | 1件 | 1件 | 約1.5-2KB |
| **平均** | 5-10件 | 5-10件 | 約5-10KB |
| **最大** | 20件以上 | 20件以上 | 約15-25KB |

**計算式**:
```
基本フィールド（約200バイト）
+ photos配列（画像数 × 約700バイト）
+ screenshots配列（画像数 × 約700バイト）
+ thumbnails配列（最大2要素 × 約700バイト）
+ thumbnailオブジェクト（約700バイト）
```

## 3. データ量の推定

### 3.1 想定シナリオ

| 項目 | 値 |
|------|-----|
| 拠点内ユーザー数 | 10-50人 |
| 1ユーザーあたりの記録日数 | 30-365日 |
| 1日あたりの記録数 | 1-5件 |
| 1記録あたりの画像数 | 写真: 5-10件、スクリーンショット: 5-10件 |

### 3.2 計算例

#### シナリオ1: 小規模拠点（短期間）
- ユーザー数: 10人
- 記録日数: 30日
- 1日あたりの記録: 1件
- 総レコード数: 10 × 30 × 1 = **300件**

**データ量**:
- 最小: 300件 × 1.5KB = **約450KB**
- 平均: 300件 × 7KB = **約2.1MB**
- 最大: 300件 × 20KB = **約6MB**

#### シナリオ2: 中規模拠点（標準期間）
- ユーザー数: 30人
- 記録日数: 90日
- 1日あたりの記録: 2件
- 総レコード数: 30 × 90 × 2 = **5,400件**

**データ量**:
- 最小: 5,400件 × 1.5KB = **約8.1MB**
- 平均: 5,400件 × 7KB = **約37.8MB**
- 最大: 5,400件 × 20KB = **約108MB**

#### シナリオ3: 大規模拠点（長期期間）
- ユーザー数: 50人
- 記録日数: 365日
- 1日あたりの記録: 3件
- 総レコード数: 50 × 365 × 3 = **54,750件**

**データ量**:
- 最小: 54,750件 × 1.5KB = **約82.1MB**
- 平均: 54,750件 × 7KB = **約383.3MB**
- 最大: 54,750件 × 20KB = **約1.1GB**

## 4. S3料金の試算

### 4.1 AWS S3料金体系（ap-northeast-1リージョン）

本システムでは、AWS S3の東京リージョン（ap-northeast-1）を使用しています。記録・証拠データの取得時に発生するS3料金は以下の通りです。

#### 4.1.1 リクエスト料金

| 操作 | 料金（1,000リクエストあたり） |
|------|---------------------------|
| **GETリクエスト** | 0.0004 USD |
| **LISTリクエスト** | 0.0005 USD |

#### 4.1.2 データ転送料金

S3からインターネットへのデータ転送（月間転送量に応じて）:

| 転送量 | 料金（1GBあたり） |
|--------|-----------------|
| 最初の1GB | **無料** |
| 1GB〜10TB | 0.09 USD |
| 10TB〜50TB | 0.085 USD |
| 50TB〜150TB | 0.07 USD |
| 150TB以上 | 0.05 USD |

**注意**: 同一リージョン内（EC2からS3への転送など）は無料です。

### 4.2 記録・証拠タブでのS3操作

#### 4.2.1 全件検索時のS3操作

1. **LIST操作（listObjectsV2）**
   - 各ユーザー、各日付プレフィックスごとに実行
   - 1回のLIST操作で最大1,000オブジェクトを取得可能
   - オブジェクト数が多い場合は複数回のLIST操作が必要

2. **プレサインドURL生成（getSignedUrl）**
   - 各画像オブジェクトに対してURLを生成
   - **この操作自体は料金がかからない**（URL生成のみ）

3. **実際の画像データ取得（GET操作）**
   - ユーザーが画像を表示する際にプレサインドURL経由で取得
   - この操作でGETリクエスト料金とデータ転送料金が発生

### 4.3 料金試算

#### 4.3.1 前提条件

- **リージョン**: ap-northeast-1（東京）
- **画像ファイルサイズ**: 
  - カメラ画像: 平均50-200KB（圧縮後）
  - スクリーンショット: 平均100-500KB（圧縮後）
- **1日あたりの画像数**: 写真10件、スクリーンショット10件（合計20件/日）
- **画像表示率**: 全件検索で取得した画像のうち、実際に表示される割合を30%と仮定

#### 4.3.2 シナリオ別の料金試算

##### シナリオ1: 小規模拠点（300レコード、30日間）

**S3操作**:
- LIST操作: 約10ユーザー × 30日 = 300回
- 画像オブジェクト数: 300レコード × 20件/日 = 6,000件
- 実際に表示される画像: 6,000件 × 30% = 1,800件

**料金計算**:
- LISTリクエスト料金: 300回 ÷ 1,000 × 0.0005 USD = **0.00015 USD**
- GETリクエスト料金: 1,800回 ÷ 1,000 × 0.0004 USD = **0.00072 USD**
- データ転送料金: 
  - 平均画像サイズ150KB × 1,800件 = 270MB
  - 1GB未満のため **無料**
- **合計: 約0.00087 USD（約0.13円）**

##### シナリオ2: 中規模拠点（5,400レコード、90日間）

**S3操作**:
- LIST操作: 約30ユーザー × 90日 = 2,700回
- 画像オブジェクト数: 5,400レコード × 20件/日 = 108,000件
- 実際に表示される画像: 108,000件 × 30% = 32,400件

**料金計算**:
- LISTリクエスト料金: 2,700回 ÷ 1,000 × 0.0005 USD = **0.00135 USD**
- GETリクエスト料金: 32,400回 ÷ 1,000 × 0.0004 USD = **0.01296 USD**
- データ転送料金: 
  - 平均画像サイズ150KB × 32,400件 = 4.86GB
  - 最初の1GB: 無料
  - 残り3.86GB × 0.09 USD/GB = **0.3474 USD**
- **合計: 約0.36171 USD（約54円）**

##### シナリオ3: 大規模拠点（54,750レコード、365日間）

**S3操作**:
- LIST操作: 約50ユーザー × 365日 = 18,250回
- 画像オブジェクト数: 54,750レコード × 20件/日 = 1,095,000件
- 実際に表示される画像: 1,095,000件 × 30% = 328,500件

**料金計算**:
- LISTリクエスト料金: 18,250回 ÷ 1,000 × 0.0005 USD = **0.009125 USD**
- GETリクエスト料金: 328,500回 ÷ 1,000 × 0.0004 USD = **0.1314 USD**
- データ転送料金: 
  - 平均画像サイズ150KB × 328,500件 = 49.275GB
  - 最初の1GB: 無料
  - 残り48.275GB × 0.09 USD/GB = **4.34475 USD**
- **合計: 約4.485275 USD（約673円）**

### 4.5 コスト最適化の推奨事項

#### 4.5.1 画像表示の最適化

1. **遅延読み込み（Lazy Loading）**
   - 画面に表示される画像のみを読み込む
   - 画像表示率を30%以下に抑えることで、コストを大幅に削減可能

2. **サムネイルの活用**
   - 一覧表示ではサムネイルのみを表示
   - 詳細表示時のみフルサイズ画像を取得

3. **キャッシュの活用**
   - 一度取得した画像をブラウザキャッシュに保存
   - 再表示時はS3から取得せず、キャッシュから読み込む

#### 4.5.2 リクエスト数の削減

1. **ページネーションの徹底**
   - 全件取得ではなく、必要な分だけ取得
   - ユーザーがスクロールした際に追加データを取得

2. **日付範囲の絞り込み**
   - 全期間ではなく、必要な期間のみを指定
   - デフォルトで直近30日間のみを表示

#### 4.5.3 データ転送量の削減

1. **画像の圧縮**
   - アップロード時に適切な圧縮を実施
   - サムネイル用の低解像度画像を別途保存

2. **CDNの活用**
   - CloudFrontなどのCDNを使用して転送コストを削減
   - 同一リージョン内の転送は無料のため、EC2からS3への転送はコストがかからない

### 4.6 料金監視の推奨事項

#### 4.6.1 AWS Cost Explorerでの監視

- S3のリクエスト数とデータ転送量を定期的に確認
- 異常な増加がないか監視

#### 4.6.2 アラートの設定

- 月間のS3料金が一定額（例: 10,000円）を超えた場合にアラート
- 1日のリクエスト数が異常に多い場合にアラート

## 5. パフォーマンスへの影響

### 4.1 バックエンド側の影響

#### メモリ使用量
- **全件をメモリに展開**: バックエンドでは全レコードを配列として保持するため、メモリ使用量が大きくなる
- **例**: 5,400件 × 7KB = 約37.8MB のメモリを一時的に使用

#### 処理時間
1. **S3リスト操作**: 各ユーザーのS3プレフィックスから全オブジェクトをリストアップ
2. **プレサインドURL生成**: 各画像オブジェクトに対して1時間有効なURLを生成
3. **データグループ化**: 日付ごとに写真とスクリーンショットを分類
4. **ソート処理**: 日付順でソート

**推定処理時間**（5,400件の場合）:
- S3リスト操作: 約5-10秒
- プレサインドURL生成: 約10-20秒
- データ処理: 約2-5秒
- **合計: 約17-35秒**

### 4.2 フロントエンド側の影響

#### ネットワーク転送
- JSONレスポンスのサイズが大きい場合、転送に時間がかかる
- 例: 37.8MB の転送には、10Mbps回線で約30秒、100Mbps回線で約3秒

#### ブラウザのメモリ使用量
- 大量のデータを一度にDOMにレンダリングすると、ブラウザのメモリ使用量が増加
- 例: 5,400件を一度に表示すると、ブラウザのメモリ使用量が100MB以上増加する可能性

#### レンダリング時間
- 大量のテーブル行を一度にレンダリングすると、画面のフリーズが発生する可能性

## 6. 推奨事項

### 5.1 全件検索の実装方法

#### フロントエンド側
```javascript
// 全件取得する場合は、limitを大きく指定
const response = await getCaptureRecords(
  selectedUserId || null,
  startDate || null,
  endDate || null,
  currentSatelliteId || null,
  1,  // page
  10000  // limit: 全件取得を想定した大きな値
);
```

#### バックエンド側
- メモリ使用量の監視を実装
- レコード数が一定以上（例: 10,000件）の場合は警告ログを出力
- 必要に応じてストリーミング処理やチャンク取得を検討

### 5.2 パフォーマンス最適化の提案

#### 1. 仮想スクロールの実装
- フロントエンドで仮想スクロールを実装し、表示領域のみをレンダリング
- 例: `react-window` や `react-virtualized` を使用

#### 2. ページネーションの活用
- 全件取得ではなく、ページネーションを活用して必要な分だけ取得
- ユーザーが「次のページ」をクリックした際に追加データを取得

#### 3. バックエンドの最適化
- S3リスト操作の並列化
- プレサインドURL生成の最適化（必要に応じてキャッシュ）
- データベースインデックスの最適化

#### 4. キャッシュの活用
- 頻繁にアクセスされるデータはキャッシュに保存
- キャッシュの有効期限を適切に設定（例: 5分）

### 5.3 運用上の注意点

#### 監視項目
- バックエンドのメモリ使用量
- APIレスポンス時間
- フロントエンドのレンダリング時間
- ネットワーク転送量

#### 制限の設定
- 1回のリクエストで取得できる最大件数を制限（例: 10,000件）
- 超過した場合はエラーメッセージを返すか、ページネーションを強制

## 7. 実装上の注意点

### 6.1 現在の実装の制約

1. **メモリ使用量**: 全件をメモリに展開するため、大量データの場合にメモリ不足のリスク
2. **処理時間**: S3操作とプレサインドURL生成に時間がかかる
3. **ネットワーク転送**: 大きなJSONレスポンスの転送に時間がかかる

### 6.2 改善の余地

#### 短期的な改善
- ページネーションのデフォルト値を適切に設定
- 全件取得時の警告メッセージを表示
- ローディングインジケーターの改善

#### 長期的な改善
- ストリーミング処理の実装
- バックグラウンドジョブでのデータ取得
- データの事前集計とキャッシュ

### 6.3 テスト推奨事項

#### 負荷テスト
- 異なる規模のデータセットでテスト
  - 小規模: 1,000件
  - 中規模: 5,000件
  - 大規模: 10,000件以上

#### パフォーマンステスト
- レスポンス時間の測定
- メモリ使用量の監視
- ネットワーク転送量の測定

## 7. まとめ

### 7.1 主要なポイント

1. **データ量**: レコード数に応じて数MBから数GBまで変動
2. **パフォーマンス**: 大量データの場合、処理時間とメモリ使用量が増加

## 付録: S3料金計算の詳細

### 計算式

#### LISTリクエスト料金
```
LISTリクエスト料金 = (LIST操作回数 ÷ 1,000) × 0.0005 USD
```

#### GETリクエスト料金
```
GETリクエスト料金 = (GET操作回数 ÷ 1,000) × 0.0004 USD
```

#### データ転送料金
```
データ転送料金 = 0 USD（最初の1GBは無料）
              + (転送量 - 1GB) × 0.09 USD/GB（1GB〜10TBの場合）
```

#### 合計料金
```
合計料金 = LISTリクエスト料金 + GETリクエスト料金 + データ転送料金
```

### 為替レート

本ドキュメントでは、1 USD = 150円として計算しています（2026年1月時点の概算）。
