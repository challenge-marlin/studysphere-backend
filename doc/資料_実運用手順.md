# StudySphere 実運用のための手順書

## 1. 前提条件

### 1.1 必要なソフトウェア

以下のソフトウェアがインストールされている必要があります：

- **Git**: バージョン管理システム（GitHubからのダウンロード用）
- **Docker Desktop**: DockerとDocker Composeが含まれたアプリケーション
- **Node.js**: バージョン16以上（推奨：20.x）
- **npm**: Node.jsに付属（Node.jsインストール時に自動インストール）

### 1.2 システム要件

- **OS**: Windows 10/11
- **メモリ**: 8GB以上（推奨：16GB）
- **ストレージ**: 10GB以上の空き容量
- **ネットワーク**: インターネット接続（初回ダウンロード・パッケージインストール時）

## 2. GitHubからのダウンロード手順

### 2.1 リポジトリのクローン

1. **コマンドプロンプトまたはPowerShellを開く**

2. **プロジェクトを保存するディレクトリに移動**
   ```powershell
   cd C:\Users\ユーザー名\Documents
   # または任意のディレクトリ
   ```

3. **GitHubリポジトリをクローン**
   ```powershell
   git clone https://github.com/[リポジトリURL]/studysphere.git
   ```
   > **注意**: `[リポジトリURL]`は実際のGitHubリポジトリURLに置き換えてください。

4. **プロジェクトディレクトリに移動**
   ```powershell
   cd studysphere
   ```

### 2.2 ZIPファイルからの展開（代替方法）

Gitがインストールされていない場合は、ZIPファイルをダウンロードして展開：

1. GitHubのリポジトリページにアクセス
2. 「Code」ボタンをクリック
3. 「Download ZIP」を選択
4. ZIPファイルをダウンロード
5. 適切な場所に展開（例：`C:\Users\ユーザー名\Documents\studysphere`）

## 3. 初回セットアップ

### 3.1 Docker Desktopの起動

1. **Docker Desktopを起動**
   - スタートメニューから「Docker Desktop」を検索して起動
   - システムトレイにDockerアイコンが表示されることを確認
   - Docker Desktopが完全に起動するまで待つ（通常1～2分）

2. **Dockerの動作確認**
   ```powershell
   docker --version
   docker compose version
   ```
   両方のコマンドが正常に実行されることを確認

### 3.2 フロントエンドの依存関係インストール（オプション）

フロントエンドをローカルで開発する場合のみ必要：

1. **フロントエンドディレクトリに移動**
   ```powershell
   cd studysphere-frontend
   ```

2. **依存関係をインストール**
   ```powershell
   npm install
   ```
   > **注意**: 初回インストールには数分かかることがあります。

3. **プロジェクトルートに戻る**
   ```powershell
   cd ..
   ```

### 3.3 環境変数の設定（必要に応じて）

本番環境や特定の設定が必要な場合は、`.env`ファイルを作成：

1. **studysphere-backendディレクトリに移動**
   ```powershell
   cd studysphere-backend
   ```

2. **環境変数ファイルの作成（必要な場合のみ）**
   - `.env`ファイルを作成し、必要な環境変数を設定
   - デフォルト設定で動作する場合は不要

3. **プロジェクトルートに戻る**
   ```powershell
   cd ..
   ```

## 4. システムの起動手順

### 4.1 バックエンドディレクトリに移動

```powershell
cd studysphere-backend
```

### 4.2 起動スクリプトの実行

**方法1: ダブルクリックで起動（推奨）**

1. エクスプローラーで`studysphere-backend`フォルダを開く
2. `start-all.bat`をダブルクリック
3. 新しいコマンドプロンプトウィンドウが開き、起動処理が開始されます

**方法2: コマンドラインから起動**

```powershell
.\start-all.bat
```

### 4.3 起動モードの選択

`start-all.bat`を実行すると、以下のメニューが表示されます：

```
[INFO] Select startup mode:
  1) Normal (with health checks)
  2) Quick (fast startup, minimal checks)
  3) Recreate (--force-recreate)
  4) Rebuild + Recreate (build -> up --force-recreate)
```

**推奨**: 初回起動時は **「1」** を選択（Enterキーを押す）

- **1) Normal**: 正常起動（ヘルスチェックあり、推奨）
- **2) Quick**: 高速起動（ヘルスチェックなし）
- **3) Recreate**: 既存コンテナを強制再作成
- **4) Rebuild + Recreate**: イメージを再ビルドしてコンテナを再作成

起動処理が開始されると、以下のようなログが表示されます：

### 4.6 フロントエンドの起動（必要に応じて）

フロントエンドをローカルで起動する場合：

1. **新しいコマンドプロンプトまたはPowerShellウィンドウを開く**

2. **フロントエンドディレクトリに移動**
   ```powershell
   cd C:\Users\ユーザー名\Documents\studysphere\studysphere-frontend
   ```

3. **開発サーバーを起動**
   ```powershell
   npm start
   ```

4. **ブラウザでアクセス**
   - 自動的にブラウザが開き、`http://localhost:3000`にアクセスされます
   - 開かない場合は、手動でブラウザを開いてアクセスしてください

## 5. システムの動作確認

### 5.1 バックエンドAPIの確認

1. **ブラウザでアクセス**
   - `http://localhost:5050` にアクセス
   - または `http://localhost:5050/api/health` にアクセスしてヘルスチェックを確認

2. **コマンドラインから確認**
   ```powershell
   curl http://localhost:5050/api/health
   ```

### 5.2 データベースの確認

1. **Dockerコンテナの状態確認**
   ```powershell
   docker compose ps
   ```
   `db`と`backend`（または`express_app`）が`Up`状態であることを確認

2. **データベースログの確認（オプション）**
   ```powershell
   docker compose logs db
   ```

### 5.3 ログインの確認

1. **フロントエンドにアクセス**
   - `http://localhost:3000` にアクセス

2. **管理者でログイン**
   - **ID**: `admin001`
   - **パスワード**: `admin123`

3. **ログイン成功を確認**
   - ダッシュボードが表示されることを確認

## 6. システムの停止手順

### 6.1 停止スクリプトの実行

**方法1: ダブルクリックで停止（推奨）**

1. エクスプローラーで`studysphere-backend`フォルダを開く
2. `stop-all.bat`をダブルクリック
3. 停止処理が実行されます

**方法2: コマンドラインから停止**

```powershell
cd studysphere-backend
.\stop-all.bat
```

### 6.2 停止処理の確認

停止処理が開始されると、以下のようなログが表示されます：

```
========================================
StudySphere Development Environment
========================================
[INFO] Stopping all services...
[INFO] Stopping Node.js processes...
[OK] Node.js processes stopped.
[INFO] Stopping services gracefully...
[OK] All services stopped successfully.
[INFO] Cleaning up Docker resources...
[OK] Stopped containers removed.
[OK] Unused images removed.
[OK] Unused networks removed.
[OK] Build cache removed.
[INFO] StudySphere Environment stopped and cleaned up.
[INFO] Note: Database volumes are preserved to keep your data.
```

### 6.3 フロントエンドの停止

フロントエンドを起動している場合：

1. **フロントエンドのコマンドプロンプトウィンドウで**
   - `Ctrl + C` を押して停止
   - またはウィンドウを閉じる

### 6.4 Docker Desktopの停止（オプション）

完全にDockerを停止する場合：

1. **システムトレイのDockerアイコンを右クリック**
2. **「Quit Docker Desktop」を選択**

> **注意**: Docker Desktopを停止すると、次回起動時にコンテナを再起動する必要があります。

## 7. トラブルシューティング

### 7.1 Dockerが起動しない

**症状**: `[ERROR] Docker is not running.` と表示される

**解決方法**:
1. Docker Desktopが起動しているか確認
2. システムトレイにDockerアイコンが表示されているか確認
3. Docker Desktopを再起動してみる

### 7.2 ポートが既に使用されている

**症状**: `Port 5050 is already in use` などのエラー

**解決方法**:
1. 既存のプロセスを確認
   ```powershell
   netstat -ano | findstr :5050
   ```
2. プロセスを終了するか、別のポートを使用するように設定変更

### 7.3 データベース接続エラー

**症状**: `[ERROR] Database connection failed` と表示される

**解決方法**:
1. データベースコンテナが起動しているか確認
   ```powershell
   docker compose ps
   ```
2. データベースログを確認
   ```powershell
   docker compose logs db
   ```
3. コンテナを再起動
   ```powershell
   docker compose restart db
   ```

### 7.4 バックエンドが起動しない

**症状**: `[ERROR] Backend health check failed` と表示される

**解決方法**:
1. バックエンドログを確認
   ```powershell
   docker compose logs backend
   ```
2. Node.jsの依存関係を再インストール（バックエンドディレクトリで）
   ```powershell
   cd backend
   npm install
   ```
3. コンテナを再ビルド
   ```powershell
   docker compose up -d --build
   ```

### 7.5 ログファイルの確認

ログは以下のディレクトリに保存されます：

```
studysphere-backend\logs\YYYY\MM\DD\
  ├── startup.log           # 起動ログ
  ├── startup-errors.log    # エラーログ
  ├── db-error.log          # データベースエラーログ
  ├── backend-error.log     # バックエンドエラーログ
  ├── admin-setup.log       # 管理者セットアップログ
  └── service-status.log    # サービス状態ログ
```

## 8. 日常的な運用手順

### 8.1 毎日の起動

1. **Docker Desktopを起動**
2. **`start-all.bat`を実行**
3. **起動完了を確認**
4. **ブラウザでアクセスして動作確認**

### 8.2 毎日の停止

1. **すべての作業を保存**
2. **`stop-all.bat`を実行**
3. **停止完了を確認**
4. **必要に応じてDocker Desktopを停止**

### 8.3 データバックアップ（推奨）

定期的なデータバックアップを実施することを推奨します：

1. **Dockerボリュームのバックアップ**
   ```powershell
   docker compose down
   docker run --rm -v studysphere-backend_mysql_data:/data -v ${PWD}:/backup alpine tar czf /backup/mysql-backup-$(date +%Y%m%d).tar.gz /data
   docker compose up -d
   ```

2. **または、MySQLの直接バックアップ**
   ```powershell
   docker compose exec db mysqldump -u root -pshinomoto926! curriculum-portal > backup-$(date +%Y%m%d).sql
   ```

## 9. 重要な注意事項

### 9.1 データの保持

- `stop-all.bat`を実行しても、**データベースのデータは保持されます**
- データを完全に削除したい場合は、明示的にボリュームを削除する必要があります

### 9.2 管理者アカウント

- 初期管理者アカウント:
  - **ID**: `admin001`
  - **パスワード**: `admin123`
  - 初回ログイン後、パスワードを変更することを強く推奨します

### 9.3 ポート番号

- バックエンドAPI: `5050`
- フロントエンド: `3000`
- MySQL: `3307`（ホスト側からアクセスする場合）

### 9.4 ログの管理

- ログファイルは自動的に日付別に整理されます
- ディスク容量に注意し、定期的に古いログを削除することを推奨します

## 10. よくある質問（FAQ）

**Q: 起動に時間がかかりますか？**

A: 初回起動時は数分かかる場合があります（イメージのダウンロード、データベースの初期化など）。2回目以降は通常1～2分で起動します。

**Q: フロントエンドを起動する必要がありますか？**

A: フロントエンドは本番環境では別途ホスティングされる場合があります。ローカル開発時のみ起動が必要です。

**Q: データベースのデータを削除したい場合は？**

A: 以下のコマンドでボリュームを削除できます（**注意**: すべてのデータが削除されます）：
```powershell
docker compose down -v
```

**Q: バックエンドのコードを変更した場合、再起動が必要ですか？**

A: 開発環境では、コード変更時に自動的に再起動されるホットリロード機能が有効になっています。変更が反映されない場合は、コンテナを再起動してください。
